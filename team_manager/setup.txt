# PRD — Team Resource Manager

> Questo documento è il riferimento completo per costruire l'intera applicazione.
> Claude Code deve leggere questo file integralmente prima di scrivere qualsiasi codice.

---

## 1. Obiettivo del Prodotto

Tool web per la gestione delle risorse di un team di sviluppo su una timeline settimanale organizzata per sprint. Permette di visualizzare e pianificare quanti giorni ogni persona lavora su ogni feature, settimana per settimana, con alert automatici di sovraccarico e gestione delle ferie.

## 3. Schema Database Supabase

Eseguire nell'ordine nell'editor SQL di Supabase:

```sql
-- =============================================
-- ROLES
-- =============================================
CREATE TABLE roles (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,
  color       TEXT NOT NULL DEFAULT '#6366F1', -- hex color
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- =============================================
-- TEAM MEMBERS
-- =============================================
CREATE TABLE team_members (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,
  role_id     UUID REFERENCES roles(id) ON DELETE SET NULL,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- =============================================
-- SPRINTS
-- =============================================
CREATE TABLE sprints (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name           TEXT NOT NULL,           -- es. "Sprint 150"
  start_date     DATE NOT NULL,
  duration_weeks INTEGER NOT NULL DEFAULT 2 CHECK (duration_weeks IN (1, 2, 3)),
  created_at     TIMESTAMPTZ DEFAULT now()
);

-- =============================================
-- FEATURES
-- =============================================
CREATE TABLE features (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,
  type        TEXT NOT NULL CHECK (type IN ('ktlo', 'small_change', 'strategic_initiative')),
  sprint_id   UUID REFERENCES sprints(id) ON DELETE SET NULL,
  order_index INTEGER NOT NULL DEFAULT 0,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- =============================================
-- ALLOCATIONS (giorni lavoro per persona/feature/settimana)
-- =============================================
CREATE TABLE allocations (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  feature_id      UUID NOT NULL REFERENCES features(id) ON DELETE CASCADE,
  team_member_id  UUID NOT NULL REFERENCES team_members(id) ON DELETE CASCADE,
  week_start      DATE NOT NULL,  -- sempre un lunedì
  days            NUMERIC(3,1) NOT NULL DEFAULT 0
                    CHECK (days >= 0 AND days <= 5),
  UNIQUE (feature_id, team_member_id, week_start)
);

-- =============================================
-- TIME OFF / FERIE (globale per persona/settimana)
-- =============================================
CREATE TABLE time_off (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  team_member_id  UUID NOT NULL REFERENCES team_members(id) ON DELETE CASCADE,
  week_start      DATE NOT NULL,  -- sempre un lunedì
  days_off        NUMERIC(3,1) NOT NULL DEFAULT 5
                    CHECK (days_off >= 0 AND days_off <= 5),
  UNIQUE (team_member_id, week_start)
);

-- =============================================
-- RLS (disabilitato per semplicità, abilitare in produzione)
-- =============================================
ALTER TABLE roles         ENABLE ROW LEVEL SECURITY;
ALTER TABLE team_members  ENABLE ROW LEVEL SECURITY;
ALTER TABLE sprints        ENABLE ROW LEVEL SECURITY;
ALTER TABLE features       ENABLE ROW LEVEL SECURITY;
ALTER TABLE allocations    ENABLE ROW LEVEL SECURITY;
ALTER TABLE time_off       ENABLE ROW LEVEL SECURITY;

-- Policy temporanea: accesso pubblico (per sviluppo)
CREATE POLICY "public_all" ON roles          FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "public_all" ON team_members   FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "public_all" ON sprints         FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "public_all" ON features        FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "public_all" ON allocations     FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "public_all" ON time_off        FOR ALL USING (true) WITH CHECK (true);
```

## 6. Logica Capacity (`src/lib/capacity.ts`)

```typescript
import { Allocation, TimeOff, Feature, CapacityInfo } from '../types';

/**
 * Calcola la capacity di un membro per una specifica settimana.
 * Considera tutte le allocazioni su tutte le feature + le ferie.
 */
export function getCapacityInfo(
  memberId: string,
  weekStart: string,
  allocations: Allocation[],
  timeOffList: TimeOff[],
  features: Feature[]
): CapacityInfo {
  // Giorni di ferie questa settimana
  const timeOff = timeOffList.find(
    t => t.team_member_id === memberId && t.week_start === weekStart
  );
  const daysOff = timeOff?.days_off ?? 0;
  const availableDays = 5 - daysOff;

  // Tutte le allocazioni di questa persona questa settimana
  const weekAllocations = allocations.filter(
    a => a.team_member_id === memberId && a.week_start === weekStart && a.days > 0
  );

  const totalDays = weekAllocations.reduce((sum, a) => sum + a.days, 0);

  const breakdown = weekAllocations.map(a => {
    const feature = features.find(f => f.id === a.feature_id);
    return {
      featureId: a.feature_id,
      featureName: feature?.name ?? 'Feature sconosciuta',
      days: a.days,
    };
  });

  return {
    totalDays,
    availableDays,
    isOverCapacity: totalDays > availableDays,
    breakdown,
  };
}

/**
 * Genera l'elenco di settimane (lunedì) coperte dagli sprint.
 * Se non ci sono sprint, genera le prossime 8 settimane da oggi.
 */
export function generateWeekColumns(sprints: import('../types').Sprint[]): import('../types').WeekColumn[] {
  const { startOfWeek, addWeeks, format, parseISO } = require('date-fns');
  
  if (sprints.length === 0) {
    const today = new Date();
    const start = startOfWeek(today, { weekStartsOn: 1 });
    return Array.from({ length: 8 }, (_, i) => {
      const date = addWeeks(start, i);
      return {
        weekStart: format(date, 'yyyy-MM-dd'),
        label: format(date, 'd MMM'),
        sprintId: null,
        sprintName: null,
      };
    });
  }

  const sorted = [...sprints].sort((a, b) =>
    a.start_date.localeCompare(b.start_date)
  );

  const columns: import('../types').WeekColumn[] = [];

  for (const sprint of sorted) {
    const sprintStart = startOfWeek(parseISO(sprint.start_date), { weekStartsOn: 1 });
    for (let w = 0; w < sprint.duration_weeks; w++) {
      const date = addWeeks(sprintStart, w);
      const weekStart = format(date, 'yyyy-MM-dd');
      if (!columns.find(c => c.weekStart === weekStart)) {
        columns.push({
          weekStart,
          label: format(date, 'd MMM'),
          sprintId: sprint.id,
          sprintName: sprint.name,
        });
      }
    }
  }

  return columns;
}

/**
 * Calcola gli SprintSpan (quante colonne occupa ogni sprint nell'header).
 */
export function getSprintSpans(weeks: import('../types').WeekColumn[]): import('../types').SprintSpan[] {
  const spans: import('../types').SprintSpan[] = [];
  let i = 0;
  while (i < weeks.length) {
    const week = weeks[i];
    if (!week.sprintId) {
      i++;
      continue;
    }
    let count = 1;
    while (
      i + count < weeks.length &&
      weeks[i + count].sprintId === week.sprintId
    ) {
      count++;
    }
    spans.push({
      sprintId: week.sprintId,
      sprintName: week.sprintName!,
      startColIndex: i,
      colSpan: count,
    });
    i += count;
  }
  return spans;
}
```

## 8. Comportamenti e Regole di Business

### Calcolo capacity

Per ogni `(team_member_id, week_start)`:

```
giorni_disponibili = 5 - time_off.days_off   (default 5 se nessuna ferie)
giorni_allocati    = SUM(allocations.days WHERE team_member_id AND week_start)

sovraccapacity = giorni_allocati > giorni_disponibili
```

Il calcolo avviene **lato client** aggregando i dati già in memoria.

### Alert ferie

Quando si inseriscono ferie per una settimana, se la persona ha già allocazioni in quella settimana, ricalcolare immediatamente il capacity check → eventuali celle diventano rosse.

### Sincronizzazione ferie

Le righe ferie in ogni feature group mostrano gli stessi dati (da `time_off`). Modificare il valore in un punto aggiorna il singolo record `time_off` — le altre righe ferie si aggiornano di conseguenza tramite lo store Zustand.

### Ordine feature

Le feature vengono mostrate per `order_index ASC`. Non serve drag-and-drop per ora (v1).

### Settimane visualizzate

Le settimane in timeline = unione di tutte le settimane coperte dagli sprint, in ordine cronologico. Se non ci sono sprint, mostrare le 8 settimane correnti.

## 13. Edge Cases da Gestire

1. **Nessun membro nel team**: TimelineView mostra messaggio "Aggiungi prima i membri del team" con link a `/team`
2. **Nessuno sprint**: mostrare le 8 settimane correnti, avvisare che non ci sono sprint configurati
3. **Nessuna feature**: mostrare empty state con pulsante "Aggiungi la prima feature"
4. **Errori Supabase**: mostrare toast di errore via Sonner, non crashare l'app
5. **Valore allocation non valido**: validare lato client (0 ≤ days ≤ 5, step 0.5) prima di salvare
6. **Sprint sovrapposti**: non bloccare, ma gestire le settimane duplicate (deduplicare in `generateWeekColumns`)
7. **Membro senza ruolo**: mostrare badge grigio con testo "Nessun ruolo"

## 15. Note Finali

- Tutto il codice deve essere in **TypeScript strict** (no `any`)
- Usare `async/await` con try/catch per tutte le chiamate Supabase
- I `week_start` devono essere **sempre lunedì** — usare `startOfWeek(date, { weekStartsOn: 1 })` da date-fns
- Gli upsert delle allocazioni usano `onConflict: 'feature_id,team_member_id,week_start'`
- Gli upsert delle ferie usano `onConflict: 'team_member_id,week_start'`
- **Non implementare** autenticazione in v1 (le RLS policy sono permissive)
- **Non implementare** drag-and-drop per l'ordine feature in v1
- **Non implementare** realtime Supabase subscriptions in v1
